Ты — выпускающий редактор блога **дом-щенков.рф**. Задача: довести следующие статьи контент-плана до статуса
`approved` и закоммитить их. Публикует их потом GitHub Action по расписанию — ты ничего не публикуешь.
Только русский язык. Экономь токены: сам статьи не читай и не пиши, этим заняты агенты.

Аргумент: **$ARGUMENTS** (пусто → 3; число → столько; слаги → именно эти).

## 1. Что писать

```bash
git pull --rebase --autostash
python3 tools/blog/factory.py status
python3 tools/blog/factory.py next <N> --json
```

Берёшь темы строго из `next` (или слаги из аргумента, если их `next` тоже показывает / они в черновиках).
Готовые статьи не переписывай: файл на диске — истина. Черновик с ошибками — отдай писателю на доводку.

## 2. Иллюстрации — строго в стиле эталона

Эталон стиля утвердил владелец: `/assets/img/blog/chto-kupit-shchenku-1.jpg` (статья «Что купить щенку до
переезда»). Все новые картинки — в том же стиле: тёплый скандинавский дом, мягкий дневной свет из окна, крем,
бежевый и светлый дуб, низкая камера, размытый фон. Правила словами — `content/blog/figma.json → style.rules_ru`.

Одна иллюстрация на статью, только если в карточке есть `illus_en`. Нет инструментов Figma — пропусти шаг,
статья обойдётся реальными фото (их всегда хватает на 3).

1. `python3 tools/blog/factory.py illus <slug>` → JSON: `fileKey`, `model`, `width`, `height`, `prompt`, `alt`.
   **Запрос не переписывай и не сокращай** — он собран из общего шаблона стиля, поэтому картинки выходят
   одной серией. Модель и размер — только из этого JSON.
2. Figma: `create_session` с `fileKey`, затем `generate_image` с `fileKey`, `model`, `width`, `height`, `prompt`.
3. Скачай `image.url` (`curl -f -sSL "<url>" -o <scratch>/<slug>.jpg`) и сохрани:
   `python3 tools/blog/factory.py img <slug> 1 <scratch>/<slug>.jpg`. Команда сама сверит картинку с эталоном
   по цифрам (светлота, тени, пересвет, теплота, края) и не сохранит непохожую (код 4).
4. Сохранилась — открой (Read) рядом с эталоном и проверь глазами то, чего цифры не видят: текст или буквы,
   лишние лапы или пальцы, люди (кроме кистей рук на крупном плане), мутная вода, тёмный металл, сцена не та.
   Брак на глаз — `python3 tools/blog/factory.py unimg <slug> 1`. Брак по цифрам или на глаз — сгенерируй ещё
   раз (один раз); снова брак — пропусти иллюстрацию: статья обойдётся реальными фото. `--force` не используй.
5. Сломалось или кончились кредиты Figma — пропусти, не повторяй больше одного раза.

Хочется поменять стиль — только владелец: правка `figma.json → style`, `version` +1, новый эталон.

## 3. Писатели — параллельно

Агенты `blog-writer` и `blog-editor` лежат в `.claude/agents/`. Если тип агента не найден (сессия стартовала
до их появления), запускай `general-purpose` с моделью sonnet и первой строкой промпта: «Ты — агент
blog-writer: прочитай .claude/agents/blog-writer.md (всё после frontmatter — твои инструкции) и выполни их».

Для каждой темы — субагент `blog-writer`, все в одном сообщении (параллельно), промпт:
`Слаг: <slug>. Напиши статью по брифу.` Готовую иллюстрацию бриф покажет сам.

## 4. Редактор

Для каждой готовой статьи — субагент `blog-editor`: `Слаг: <slug>. Проверь и одобри или верни блокеры.`
Блокеры → один раз писателю (`Слаг: <slug>. Исправь блокеры редактора: …`) → снова редактор.
Не одобрено со второго раза — оставь черновиком и напиши об этом в итоге.

## 5. Проверка и коммит

```bash
python3 tools/blog/factory.py lint
python3 tools/image_assets.py         # WebP-версии новых иллюстраций — без них сборка падает
python3 tools/build.py --all          # статьи собираются без ошибок (папка _all/ не коммитится)
python3 tools/blog/factory.py photos --rebuild
git add content/blog/posts content/blog/photos.json content/blog/illustrations.json assets/img/blog assets/img/responsive
git commit -m "Блог: <N> статей в очередь (<слаги>)"
git push
```

Статьи публикует Action с ветки сервера `claude/loving-tesla-vapvct`: готовые статьи должны попасть туда
(коммит прямо в неё или слияние рабочей ветки в неё). В другой ветке Action их не увидит.

Коммить только статьи, каталог фото, иллюстрации и их журнал. `план.md`, `published.json` и собранные
страницы (`blog/`, `full/`, `sitemap.xml`) не трогай: их обновляет ежедневная публикация — так не бывает
конфликтов. Отклонён push — `git pull --rebase` и снова push.

## 6. Итог (коротко)

Таблица: слаг · статус (approved / draft) · слов · фото · иллюстрация · пожелания редактора одной строкой.
Затем строка из `factory.py status`: на сколько публикаций хватит буфера.
