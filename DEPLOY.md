# Выкладка домщенков.рф на сервер

Сайт, API заявок, база и админ-панель ставятся на один сервер тремя командами. Всё проверено на Ubuntu 26.04, 24.04 и 22.04.
Debian 12 должен работать так же, но на нём не проверялось.

**Первый этап (19.10.2026):** выкладываются главная, четыре страницы пород, политика конфиденциальности и согласие на
обработку данных — список в `src/data/publish.json`. Ссылки на остальные разделы показывают подсказку «Раздел скоро
откроется». Сервер: Timeweb Cloud (Москва, Ubuntu 26.04), `5.42.105.87`.

## Что нужно

- **Сервер в России.** Этого требует 152-ФЗ: персональные данные граждан РФ хранятся в РФ.
  Минимум 2 ГБ памяти и 20 ГБ диска, Ubuntu 24.04 или 22.04, вход по SSH под root.
- **Домен домщенков.рф** у регистратора.
- **Почта** для уведомлений Let's Encrypt о сертификате.

## 1. Направить домен на сервер

У регистратора домена создайте две A-записи на IP-адрес сервера:

| Имя | Тип | Значение |
|---|---|---|
| `@` (домщенков.рф) | A | IP сервера |
| `www` | A | IP сервера |

Обновление занимает от 15 минут до нескольких часов. Проверить с компьютера: `ping домщенков.рф` должен показать IP сервера.

## 2. Реквизиты и контакты

Пока в согласии или политике стоят `[заглушки]`, `deploy.sh` откажется выкладывать сайт. Что осталось, показывает
`python3 tools/check_launch.py`, этот же список лежит в каждом релизе: `LAUNCH-CHECKLIST.md`. Сейчас обязательных
заглушек нет.

- Реквизиты: ИП Селезнев Владимир Игоревич, ИНН, ОГРНИП — в подвале, политике и согласиях.
- **Телефон и мессенджеры на первом этапе не выводятся** (`src/data/site.json → contacts_public: false`). Вместо них
  кнопка «Оставить заявку» в «Меню» (на телефоне — в меню-бургере), в нижней панели на телефоне и в подвале. В шапке
  кнопки нет. В админке у такой заявки пометка «Заявка: меню» (мобильное меню, подвал…).
- **Почта питомника `main@домщенков.рф` видна** (`email_public: true`): в подвале, «Меню», мобильном меню, у формы
  заявки, в сообщении «не получилось отправить», в политике, в согласиях и в разметке для поисковиков. Ящик на Beget
  (MX `mx1/mx2.beget.com`).
- Срок ответа на заявку везде один: «в течение рабочего дня» (`site.json → phone.response`).
- Отозвать согласие человек может письмом на `main@домщенков.рф` или ответом питомнику на сообщение или звонок по
  своей заявке. Так написано в согласиях (версии `*-2026-10-20-2`) и в политике.
- Когда появятся настоящие телефон и ссылки на мессенджеры, впишите их в `site.json` и поставьте
  `"contacts_public": true`.

Тексты согласий фиксируются в базе при первой выкладке. Поправить их можно до неё. После — только новой версией:
скопировать версию в `consent.json` с новой датой в имени, исправить текст и переключить `current`. Иначе выкладка
остановится с ошибкой «edited after publication».

После правки: `python3 tools/build.py`, коммит, пуш. С автообновлением сервер выложит это сам, без него — `dsh update`.

## 3. Поставить на сервер

Подключитесь к серверу (`ssh root@IP`) и выполните:

```bash
apt-get update && apt-get install -y git
git clone -b claude/loving-tesla-vapvct https://github.com/VSELEZNEV54/puppyhouse.git /opt/domshchenkov/src

# один раз: Docker, nginx, файрвол, секреты, ключ бэкапов, сертификат HTTPS (5–10 минут)
/opt/domshchenkov/src/backend/deploy/server-setup.sh --email ваша@почта.ru

# сайт + API + база (первый раз 3–5 минут: собирается образ)
/opt/domshchenkov/src/backend/deploy/deploy.sh

# вход в админ-панель (пароль спросит; от 12 символов)
dsh app create-admin --login anna --name "Анна" --role admin

# новые коммиты ветки выкладываются сами, раз в 5 минут
dsh autoupdate on
```

На Timeweb Cloud команды можно вводить и без программы для SSH: карточка сервера → «Консоль».

Если `server-setup.sh` пишет, что домен не указывает на сервер, значит DNS ещё не обновился. Подождите и запустите
снова: скрипт можно запускать повторно, он ничего не перезаписывает. Если сервер пока без домена, используйте
`--no-cert`, а сертификат получите позже тем же скриптом без этого флага.

`deploy.sh` в конце сам проверяет сайт, админку, API и страницу 404. Все строки должны быть `ok`.

## 4. Сохранить ключ бэкапов

`server-setup.sh` создал ключ шифрования бэкапов `/root/domshchenkov-backup-key.txt`. Без него бэкап не
расшифровать. Скачайте ключ к себе и удалите с сервера:

```bash
scp root@IP:/root/domshchenkov-backup-key.txt .        # на своём компьютере
shred -u /root/domshchenkov-backup-key.txt             # на сервере
```

Храните ключ в надёжном месте, например в менеджере паролей.

Бэкап базы делается каждую ночь в 02:30 по Москве, хранится 20 дней в `/var/backups/domshchenkov`. Сделать бэкап
сейчас: `dsh backup`.

## 5. Проверить руками

1. Откройте https://домщенков.рф, отправьте заявку с любой страницы.
2. Откройте https://домщенков.рф/admin/, войдите. Заявка должна быть во вкладке своей породы.
3. Смените статус, добавьте комментарий.
4. Удалите тестовую заявку или отметьте её как «Спам».

## Обновления

С автообновлением (`dsh autoupdate on`) сервер раз в 5 минут смотрит, есть ли новый коммит в ветке, и выкладывает его.
Если выкладка не удалась, работает прошлая версия, а этот коммит не пересобирается, пока не придёт следующий.
Журнал: `/var/log/domshchenkov-deploy.log`, коротко — `dsh autoupdate status`. Какая версия работает, видно снаружи:
`https://домщенков.рф/api/v1/health` → `"release"`.

Вручную:

```bash
dsh update          # git pull + выкладка; при ошибке API сам вернёт прошлую версию
```

Вернуться на прошлую версию: `dsh rollback`. Ещё раз `dsh rollback` возвращает обратно. База при откате не
откатывается: миграции только добавляют.

Если ветку сольют в основную, переключите сервер: `git -C /opt/domshchenkov/src checkout <ветка> && dsh update`.

## Подключение Claude к серверу

Прямого входа на сервер у сессии Claude нет: облачная песочница не открывает SSH-соединения. Поэтому связь идёт через
GitHub:

1. Сервер настроен по шагу 3, включено `dsh autoupdate on`.
2. Claude пушит изменения в ветку — сервер сам выкладывает их в течение 5 минут.
3. Чтобы Claude мог проверить живой сайт, в настройках облачного окружения Claude (меню окружения в заголовке сессии →
   Edit → Network access) добавьте в Allowed domains `xn--b1adduihee9g.xn--p1ai` и `www.xn--b1adduihee9g.xn--p1ai`.
   Тогда Claude видит сайт и `/api/v1/health` — какая версия работает.

Логи и база остаются только на сервере. Если выкладка не прошла, пришлите вывод `dsh autoupdate status` или
`tail -n 80 /var/log/domshchenkov-deploy.log`.

## Без git: из архива

На своём компьютере выполните `tools/release.sh`. Получится `dist/domshchenkov-<версия>.tar.gz` и файл контрольной
суммы. Дальше:

```bash
scp dist/domshchenkov-<версия>.tar.gz root@IP:/opt/domshchenkov/releases/
ssh root@IP
cd /opt/domshchenkov/releases && tar --no-same-owner -xzf domshchenkov-<версия>.tar.gz
domshchenkov-<версия>/deploy.sh
```

Для первой установки в архиве тоже есть `backend/deploy/server-setup.sh`.

## Команды на сервере

| Команда | Что делает |
|---|---|
| `dsh status` | контейнеры, здоровье API, текущая версия |
| `dsh logs api` / `dsh logs worker` | последние 200 строк лога (`-f` — следить) |
| `dsh app create-admin --login olga --name "Ольга" --role manager` | сотрудник для админки |
| `dsh app reset-password --login olga` | новый пароль сотруднику |
| `dsh app --help` | все команды бэкенда: API-ключ для CRM, синхронизация каталога, удаление данных… |
| `dsh restart` | перезапуск API и воркера (после правки `/etc/domshchenkov/api.env`) |
| `dsh app notify-test` | пробное сообщение в Telegram и на почту из `api.env` |
| `dsh backup` | бэкап сейчас |
| `dsh update` / `dsh rollback` | обновить / откатить |
| `dsh autoupdate on` / `off` / `status` | автовыкладка новых коммитов раз в 5 минут |

## Уведомления о заявках

Настраиваются в `/etc/domshchenkov/api.env` (`nano /etc/domshchenkov/api.env`, сохранить — Ctrl+O, Enter, выйти —
Ctrl+X). Проверка без заявки на сайте: `dsh app notify-test` — пробное сообщение в каждый чат и на каждую почту, при
ошибке пишет, что поправить. Потом `dsh restart`, чтобы сайт взял новые настройки.

- **Telegram** — номер заявки, порода и ссылка в админку, без имени и телефона.
  1. В Telegram: @BotFather → `/newbot` → имя и адрес бота (на `bot`) → токен.
  2. Напишите боту `/start` или добавьте его в группу, где будут заявки, и напишите там `/start`.
  3. ID чата на сервере: `curl -s "https://api.telegram.org/bot<ТОКЕН>/getUpdates"` → `"chat":{"id":…}` (у группы
     ID с минусом).
  ```
  DSH_TELEGRAM_BOT_TOKEN=<токен>
  DSH_TELEGRAM_CHAT_ID=<id чата>
  ```
- **Почта** — заявка целиком (имя, телефон, порода, страница). Ящик `main@домщенков.рф` на Beget:
  ```
  DSH_SMTP_HOST=smtp.beget.com
  DSH_SMTP_PORT=465
  DSH_SMTP_SSL=true
  DSH_SMTP_USER=main@xn--b1adduihee9g.xn--p1ai
  DSH_SMTP_PASSWORD='<пароль ящика>'
  DSH_SMTP_FROM=main@xn--b1adduihee9g.xn--p1ai
  DSH_NOTIFY_EMAILS=main@xn--b1adduihee9g.xn--p1ai
  ```
  Адреса — латиницей (домен .рф как `xn--b1adduihee9g.xn--p1ai`). Пароль — в одинарных кавычках: так символы `$`,
  `#` и пробелы в нём не ломаются; кавычку `'` внутри пароля пишите как `\'`. **Timeweb Cloud по умолчанию закрывает
  порты 25, 465 и 587** — откройте 465 в панели сервера (замок у списка «Закрытые порты»), иначе письма не уйдут.
  Заявки при этом всё равно сохраняются в базе и видны в админке.
- Вебхук для CRM: `DSH_WEBHOOK_URL`, `DSH_WEBHOOK_SECRET`.

Подробно — в `backend/README.md`.

## Что где лежит

| Путь | Что |
|---|---|
| `/opt/domshchenkov/src` | копия репозитория (git) |
| `/opt/domshchenkov/releases/` | собранные версии (последние 4); `current` — ссылка на работающую |
| `/var/www/domshchenkov` | файлы сайта (nginx отдаёт только их) |
| `/etc/domshchenkov/` | секреты: `db.env` (пароли базы), `api.env` (настройки), `backup.env` |
| `/var/backups/domshchenkov` | зашифрованные бэкапы |
| Docker-том `domshchenkov_pgdata` | база PostgreSQL. **Не удалять** (`docker compose down -v` удалит все заявки) |

## Если что-то не так

- **Сайт не открывается.** Проверьте `dsh status` и `nginx -t`.
- **Формы не отправляются.** Посмотрите `dsh logs api`. Ошибки видны и в консоли браузера (F12).
- **Образы Docker не скачиваются** (Docker Hub бывает недоступен из РФ). `server-setup.sh` прописывает зеркала в
  `/etc/docker/daemon.json`. Можно указать свои в `/etc/domshchenkov/db.env`: `DSH_PYTHON_IMAGE=…`,
  `DSH_POSTGRES_IMAGE=…`.
- **Сертификат.** Продлевается сам (`certbot.timer`). Проверить продление: `certbot renew --dry-run`.
