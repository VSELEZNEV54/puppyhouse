# Развёртывание на новом проекте: по шагам

Рабочий документ. Шаги идут по порядку; каждый заканчивается проверкой,
которую видно глазами. В конце — чек-лист приёмки.

Оценка времени: **кабинеты и доступы ~30 минут**, **фронт 1–2 часа**
(зависит от того, сколько у вас кнопок и форм), **бэкенд 1–2 часа**.
Серверную часть можно отложить: без неё связка уже работает, просто часть
оплат не попадает в статистику.

---

## Шаг 0. Что потребуется

* Доступ к коду сайта (куда можно положить четыре JS-файла и подключить их
  в `<head>`).
* Node.js 18 или новее — для инструментов `seo/`. Зависимостей нет, `npm
  install` не нужен.
* Аккаунт Яндекса, которому принадлежит (или будет принадлежать) счётчик
  Метрики, и доступ к Вебмастеру.
* Аккаунт Google — для Search Console (возможно, VPN: Cloud Console из России
  может не открываться).
* Страницы «Политика конфиденциальности» и «Политика cookie» на сайте — на
  них ссылается экран согласия. Если их нет, сделайте до запуска: вы
  собираетесь спрашивать согласие, ссылаясь на документы.

---

## Шаг 1. Кабинеты

1. **Счётчик Метрики.** Создать счётчик на сайт, записать его номер.
   В настройках счётчика пока ничего не включайте — это сделает
   `goals.mjs setup` на шаге 5.
2. **Вебмастер Яндекса.** Добавить сайт, подтвердить права (проще всего
   HTML-файлом или мета-тегом), дождаться, когда появятся данные.
3. **Google Search Console.** Добавить ресурс. Тип «Домен» удобнее: он
   покрывает и `www`, и все поддомены сразу.

Проверка: все три кабинета открываются и показывают ваш сайт.

---

## Шаг 2. Доступы к API

Полностью по [2-ДОСТУПЫ-К-API.md](2-ДОСТУПЫ-К-API.md): разделы 1 (Яндекс)
и 2 (Google) обязательны, 3–6 по желанию.

```bash
cp seo/.env.example seo/.env && chmod 600 seo/.env
# вписать YANDEX_CLIENT_ID и YANDEX_CLIENT_SECRET
node seo/cli/yandex-token.mjs url
node seo/cli/yandex-token.mjs exchange <7-значный код>
```

**Проверка:**

```bash
node seo/cli/doctor.mjs
```

Яндекс.Метрика и Яндекс.Вебмастер должны быть зелёными. Если «токен получен,
но доступа нет» — вы получали токен под другим аккаунтом Яндекса, это самая
частая ошибка.

## Шаг 3. Описать проект

```bash
cp seo/project.example.json seo/project.json
```

Заполнить:

| Поле | Чем |
|---|---|
| `name`, `host`, `displayHost` | домен **в punycode**, если он кириллический |
| `metrikaCounter` | номер счётчика из шага 1 |
| `gscSiteUrl` | `sc-domain:example.ru` или `https://example.ru/` |
| `webmasterHostId` | формат `https:example.ru:443`; точное значение покажет `doctor.mjs` |
| `buildDir`, `publicDir` | где лежит собранный сайт |
| `sitemap` | адрес карты сайта |
| `indexnowKey` | 32 hex-символа, если включаете IndexNow |
| `goals`, `funnel`, `cutParams` | цели вашего продукта — см. [4-ЦЕЛИ-И-СОБЫТИЯ.md](4-ЦЕЛИ-И-СОБЫТИЯ.md) |

`project.json` коммитится: секретов в нём нет, он описывает проект.

**Проверка:** `node seo/cli/doctor.mjs` печатает имя вашего проекта и домен,
а не «example.ru».

## Шаг 4. Положить фронт

1. Скопировать четыре файла из `фронт/` туда, откуда они будут отдаваться
   по корневым адресам (`/cookie-banner.js` и т. д.).
2. **Подставить номер счётчика в трёх файлах** — в пакете там стоит `0`:

   | Файл | Строка |
   |---|---|
   | `yandex-metrika.js` | `var COUNTER_ID = 0;` |
   | `metrika-goals.js` | `var COUNTER_ID = 0;` |
   | `attribution.js` | `var COUNTER_ID = 0;` |

   (Четвёртое место — серверная настройка `metrika_counter_id`, шаг 8.)

3. Поправить в `cookie-banner.js` тексты и ссылки на свои политики.
4. Подключить в `<head>` **каждой** страницы, абсолютными путями:

```html
<script src="/cookie-banner.js?v=1" defer></script>
<script src="/yandex-metrika.js?v=1" defer></script>
<script src="/metrika-goals.js?v=1" defer></script>
<script src="/attribution.js?v=1" defer></script>
```

Подробности и что ещё можно править — в [фронт/ПОДКЛЮЧЕНИЕ.md](фронт/ПОДКЛЮЧЕНИЕ.md).

**Проверка, и проверять надо именно так:**

* откройте сайт в приватном окне — должен появиться экран согласия;
* нажмите «Только статистика» — в DevTools → Network появится запрос
  `mc.yandex.ru/metrika/tag.js`;
* **откройте самую вложенную страницу, какая есть** (`/blog/что-нибудь`) в
  новом приватном окне: экран согласия должен появиться и там. Если нет —
  путь к скрипту относительный;
* в консоли не должно быть ошибок CSP про `mc.yandex.ru`. Если есть, см.
  шаг 9.

## Шаг 5. Завести цели в счётчике

```bash
node seo/cli/goals.mjs plan     # что будет создано — ничего не меняет
node seo/cli/goals.mjs create   # создать недостающие
node seo/cli/goals.mjs setup    # воронка + электронная коммерция + обрезка GET-параметров
node seo/cli/goals.mjs list     # что теперь в счётчике
```

Команды идемпотентны: сверяются с тем, что уже есть, и делают только
недостающее. **Это не вежливость, а необходимость:** Метрика не проверяет
дубли вообще — повторный POST с тем же условием создаёт вторую цель и
отвечает 200 OK. Удалить цель через API нельзя, чистить пришлось бы руками.

Если `goals.mjs` остановился с «В seo/project.json нет списка целей» — так и
задумано, вернитесь к шагу 3.

**Проверка:** `goals.mjs list` показывает ваши цели, и их идентификаторы
посимвольно совпадают с тем, что отправляет код.

## Шаг 6. Расставить цели в коде сайта

Автоцели (клик по контакту, дочитывание статьи, уровень согласия) работают
сами. Продуктовые — расставляются руками, по одной строке в нужном месте.

**Обычная цель:**

```js
svpGoal('lead_consult', { page: location.pathname });
```

**Цель перед уходом на другую страницу — только `svpGoalThen`:**

```js
svpGoalThen('scan_start', { domain: domain }, function () {
  location.href = '/checking?url=' + encodeURIComponent(domain);
});
```

Почему не `svpGoal` + `location.href`: браузер обрывает запрос Метрики на
навигации, и цель теряется. А при строгом согласии счётчика на первой
странице часто ещё нет вовсе — `svpGoalThen` переносит цель на следующую
страницу через `sessionStorage`. Это главный шаг воронки; ошибка здесь делает
её верх слепым (см. [5-ГРАБЛИ.md](5-ГРАБЛИ.md), грабля №2).

**Покупка (если есть оплаты):**

```js
svpEcommercePurchase(orderId, price);   // доход по каналам в отчётах
svpGoal('purchase', { order: orderId });
```

**Проверка:** в приватном окне пройдите путь клиента и смотрите в
DevTools → Network фильтр `watch` — на каждую цель уходит запрос к
`mc.yandex.ru`. Через 1–2 минуты цели видны в кабинете, Отчёты → Конверсии.

## Шаг 7. Атрибуция в формах

В каждую форму, которая создаёт заявку или платёж, добавить одно поле в тело
запроса:

```js
attribution: (window.svpAttribution ? window.svpAttribution() : null)
```

На сервере — принять это поле в схеме, прогнать через
`sanitize_attribution()` и сохранить в колонку JSONB.
Подробно: [бэкенд/ПОДКЛЮЧЕНИЕ.md](бэкенд/ПОДКЛЮЧЕНИЕ.md), раздел 1.

**Проверка:** оставьте тестовую заявку, перейдя на сайт по ссылке с метками:
`?utm_source=test&utm_medium=cpc`. В уведомлении владельцу должна появиться
строка «📍 Источник: 💰 реклама — test».

## Шаг 8. Офлайн-конверсии (оплаты с сервера)

Нужно только если на сайте есть оплаты. По
[бэкенд/ПОДКЛЮЧЕНИЕ.md](бэкенд/ПОДКЛЮЧЕНИЕ.md), раздел 2:

1. получить **отдельный** `METRIKA_OAUTH_TOKEN`
   ([2-ДОСТУПЫ-К-API.md](2-ДОСТУПЫ-К-API.md), раздел 7);
2. прописать настройки, включая `metrika_counter_id`;
3. запустить `migrate_metrika_offline.py`;
4. вставить задачу Celery и расписание добора;
5. вызвать задачу в обработчике успешной оплаты;
6. **пересоздать контейнеры**, если бэкенд в Docker: `restart` не
   перечитывает `.env`.

**Проверка:** в логе после тестовой оплаты —
`Метрика: конверсия purchase_confirmed … принята`. В кабинете цель появится
с задержкой до нескольких часов: так работает загрузка офлайн-конверсий.

## Шаг 9. Если сайт отдаёт CSP-заголовок

Content-Security-Policy ломает Метрику молча — в отчётах просто меньше
данных. Нужны директивы:

```
script-src  … https://mc.yandex.ru https://mc.yandex.com
connect-src … https://mc.yandex.ru https://mc.yandex.com
img-src     … https://mc.yandex.ru
frame-src   … https://mc.yandex.ru https://mc.yandex.com
```

`frame-src` забывают чаще всего: без него `mc.yandex.ru/metrika/match.html`
падает на `default-src 'self'`, и перестаёт работать синхронизация
идентификаторов Яндекса (кросс-девайс, связка с Директом). В консоли это
видно как ошибка на каждой странице.

**Проверка:** в консоли браузера нет ни одной ошибки CSP на всех типах
страниц (главная, статья, страница результата).

## Шаг 10. Убедиться, что данные долетают

Через сутки после запуска:

```bash
node seo/cli/doctor.mjs                  # все доступы живы
node seo/cli/metrika.mjs summary         # визиты есть
node seo/cli/metrika.mjs goals --days 7  # цели срабатывают
node seo/cli/webmaster.mjs summary       # сайт в поиске
node seo/cli/report.mjs --days 28        # сводка по всем сервисам
```

Если визиты есть, а целей нет — ищите не в Метрике, а в совпадении
идентификаторов: имя в кабинете должно совпадать с именем в коде посимвольно.

## Чек-лист приёмки

Связка развёрнута, когда верно всё:

- [ ] Экран согласия появляется на главной **и на самой вложенной странице**.
- [ ] До выбора в DevTools нет ни одного запроса к `mc.yandex.ru`.
- [ ] После «Только статистика» счётчик грузится, Вебвизор не включается.
- [ ] После «Принять все» со следующего перехода работает Вебвизор.
- [ ] «Отклонить» → запросов к Метрике нет вообще.
- [ ] Главная цель воронки считается столько же раз, сколько реально
      происходит действие (сравните с серверным логом или числом записей в БД
      за те же сутки — расхождение в разы означает потерянную цель).
- [ ] `goals.mjs list` и код сайта согласованы: каждая цель из списка
      отправляется, каждая отправляемая есть в списке.
- [ ] В уведомлении о тестовой заявке есть строка «Источник».
- [ ] Тестовая оплата доехала до Метрики (строка в логе).
- [ ] В консоли нет ошибок CSP ни на одном типе страниц.
- [ ] `node seo/cli/doctor.mjs` — всё зелёное, кроме намеренно
      неподключённого.
- [ ] `seo/.env` имеет права 600 и закрыт в `.gitignore`; реальных ключей нет
      ни в одном коммите.

## Что делать дальше, когда данные пошли

| Задача | Команда |
|---|---|
| Сводка по всем сервисам | `node seo/cli/report.mjs --days 28` |
| Какие запросы приводят людей | `node seo/cli/webmaster.mjs queries` |
| Связка «запрос → страница» | `node seo/cli/webmaster.mjs monitoring` |
| Что выпало из поиска и почему | `node seo/cli/webmaster.mjs dropped` |
| Битые внутренние ссылки | `node seo/cli/webmaster.mjs broken` |
| Отправить страницу на переобход | `node seo/cli/webmaster.mjs recrawl /путь/` |
| Уведомить поиск об изменениях | `node seo/cli/indexnow.mjs changed` |
| Страницы входа из поиска | `node seo/cli/metrika.mjs landings` |
| Скорость страницы | `node seo/cli/psi.mjs` |

Полный список — в [seo/README.md](../README.md). Любая команда с `--json`
отдаёт сырые данные: так их удобнее передавать ИИ-агенту или скрипту.

## Два инструмента на будущее

Когда проектов с этой связкой станет больше одного, пригодятся ещё две
команды из набора.

```bash
node seo/cli/sync.mjs            # что и куда уедет
node seo/cli/sync.mjs add <путь> # подключить ещё один проект
node seo/cli/sync.mjs --apply    # разослать lib/ и cli/ по всем проектам
```

Инструменты живут копией в каждом проекте — так их видно там же, где
работаешь. Плата за это одна: копии разъезжаются (починил в одном месте,
забыл про второе). `sync.mjs` закрывает ровно эту дыру и **никогда** не
трогает `project.json` и данные конкретного сайта.

```bash
node seo/cli/selftest.mjs        # прогнать все читающие команды подряд
```

Запускать после любой правки инструментов. Появился он не от любви к тестам:
однажды грубая замена по тексту сломала восемь команд из десяти, и нашёл это
не автор, а заказчик. Прогон занимает минуту.
