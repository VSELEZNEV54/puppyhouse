# Аналитика под ключ — пакет для переноса на новый проект

Это рабочая связка аналитики, снятая с живого проекта «Сайт в порядке»
(сайтвпорядке.рф) и обезличенная: код, методология, инструкция по доступам
к API и описание всех грабель, на которые мы уже наступили.

По пакету аналитику разворачивают **на другом сайте, не возвращаясь в
исходный репозиторий**. Пакет читает человек или ИИ-агент — порядок чтения
одинаковый.

**Секретов в пакете нет.** Ни токенов, ни паролей, ни номеров счётчиков, ни
адресов серверов. Везде плейсхолдеры и указание, где взять настоящее значение.

---

## Что внутри связки

Четыре слоя, которые работают вместе:

1. **Фронт** — счётчик Яндекс.Метрики, который стартует только после согласия
   на cookie; цели (`reachGoal`) с очередью, переживающей переход между
   страницами; first-touch атрибуция источника посетителя.
2. **Бэкенд** — классификация источника лида для уведомлений и админки;
   досылка подтверждённых оплат в Метрику офлайн-конверсией (те оплаты,
   которые фронт не видит, потому что человек не вернулся на сайт).
3. **Доступы к API** — один OAuth-токен Яндекса на Метрику и Вебмастер,
   сервисный аккаунт Google для Search Console, ключ PageSpeed.
4. **Инструменты `seo/`** — командная строка на Node без зависимостей:
   снять данные, завести цели, найти проблемы, отправить на переобход.
   **Кабинет и браузер для ежедневной работы не нужны** — это главное, что
   даёт пакет: ИИ-агент работает с данными поиска сам.

## Быстрый старт (если читать некогда)

Минимум, после которого статистика уже собирается и видна из командной строки:

```bash
# 1. Доступы к Яндексу (10 минут в браузере) — подробно в 2-ДОСТУПЫ-К-API.md
cp seo/.env.example seo/.env && chmod 600 seo/.env
#    вписать YANDEX_CLIENT_ID и YANDEX_CLIENT_SECRET, затем:
node seo/cli/yandex-token.mjs url
node seo/cli/yandex-token.mjs exchange <7-значный код>

# 2. Описать проект
cp seo/project.example.json seo/project.json
#    заполнить host, metrikaCounter, gscSiteUrl, список goals

# 3. Проверить, что доступы живые
node seo/cli/doctor.mjs

# 4. Завести цели в счётчике
node seo/cli/goals.mjs plan      # что будет создано, ничего не меняет
node seo/cli/goals.mjs create
node seo/cli/goals.mjs setup     # воронка + e-commerce + обрезка параметров
```

Дальше — фронт: положить четыре файла из `фронт/`, подставить номер счётчика,
подключить в `<head>` **абсолютными путями** (это важно, см. грабли) и
расставить `svpGoal(...)` в кнопках и формах. Всё это в
[3-РАЗВЁРТЫВАНИЕ.md](3-РАЗВЁРТЫВАНИЕ.md).

## Чего в пакете нет

* **Реальных ключей.** Все доступы выдаются заново, от своего аккаунта;
  в пакете только `.env.example` и указание, где брать каждое значение.
* **Готового cookie-баннера под чужой бренд.** Экран согласия перенесён как
  рабочий механизм; тексты, ссылки на политику и оформление — свои.
* **Google Analytics 4, парсеров Вордстата, сторонних MCP-серверов.**
  Это намеренные отказы, причины — в методологии.
