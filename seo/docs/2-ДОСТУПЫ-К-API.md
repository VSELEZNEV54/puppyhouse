# Доступы к API: что настроено и как это повторить

Документ для того, кто сидит за клавиатурой и нажимает кнопки в кабинетах.
После него у вас есть все токены, инструменты видят данные, а ИИ-агент может
работать с поиском и статистикой **без кабинета и без браузера**.

Всё бесплатно: ни один сервис из списка не просит карту.

**Чужие ключи не используем.** Все доступы вы выдаёте от своего имени и в
любой момент отзываете (как — в конце документа).

---

## Порядок и приоритеты

| | Что | Время | Без этого |
|---|---|---|---|
| 1 | Яндекс: Метрика + Вебмастер (один токен) | ~10 мин | не видно российский поиск — обычно основной трафик |
| 2 | Google Search Console | ~15 мин | не видно вторую половину поиска |
| 3 | PageSpeed Insights | ~5 мин | нельзя измерять скорость страниц |
| 4 | IndexNow | ~2 мин | страницы дольше доходят до индекса |
| 5 | Bing Webmaster | ~5 мин | необязательно; даёт бесплатный подбор запросов |
| 6 | Яндекс.Директ | до 7 дней | нужен только при платной рекламе |
| 7 | Токен для сервера (офлайн-конверсии) | ~5 мин | в Метрику не попадут оплаты тех, кто не вернулся на сайт |

Обязательные — 1 и 2. Пункт 7 нужен, если переносите и серверную часть.

После каждого шага проверяйте себя одной командой:

```bash
node seo/cli/doctor.mjs
```

Она реально дёргает каждый сервис самым дешёвым запросом и отличает
«не подключено» от «было подключено и отвалилось» — второе важнее.

## 1. Яндекс: Метрика и Вебмастер

Один OAuth-токен закрывает оба сервиса. Приложение создаётся один раз.

### 1.1. Сначала проверьте, под каким аккаунтом вы вошли

Откройте <https://id.yandex.ru> — логин виден вверху справа.

**Это самый важный шаг во всей инструкции.** Токен получает тот аккаунт, под
которым вы залогинены в браузере, а не владелец приложения. Если открыто два
аккаунта Яндекса или второй профиль браузера — легко получить рабочий токен,
который при этом не видит ваш счётчик. Симптом потом выглядит загадочно:
«токен выдали, а доступа нет».

Нужен аккаунт, где живёт счётчик Метрики и подтверждены права на сайт
в Вебмастере.

### 1.2. Создайте приложение

<https://oauth.yandex.ru/client/new/>

1. Тип — **«Для доступа к API или отладки»**. Не «Для авторизации
   пользователей»: **тип потом не поменять**, придётся заводить заново.
2. **Название сервиса** — например `SEO Agent` (видно только вам).
3. **Контактная почта** — ваша рабочая.
4. **Доступ к данным** — вводите по одному и выбирайте из подсказки:

   | Право | Зачем |
   |---|---|
   | `metrika:read` | читать статистику (визиты, цели, страницы входа) |
   | `metrika:write` | заводить цели, воронку, настройки счётчика; отметки на графиках |
   | `webmaster:hostinfo` | **вся** информация о сайте в Вебмастере |
   | `webmaster:verify` | подтверждение прав на сайт |

   Больше ничего не добавляйте: **лишние права сокращают срок жизни токена** —
   для него берётся наименьшее ограничение среди выбранных.

   Отдельно про `webmaster:hostinfo`: в интерфейсе он подписан «Получение
   информации о внешних ссылках на сайт» и выглядит необязательным. На самом
   деле без него не работает почти весь API Вебмастера. Отметить обязательно.

5. **Создать приложение**.
6. Скопируйте **ClientID** и **Client secret**. Сохраните оба сразу: секрет
   придётся открывать заново, а сам токен Яндекс нигде не хранит вообще.

### 1.3. Впишите их в проект

```bash
cp seo/.env.example seo/.env && chmod 600 seo/.env
```

```
YANDEX_CLIENT_ID=сюда ClientID
YANDEX_CLIENT_SECRET=сюда Client secret
```

### 1.4. Получите токен

```bash
node seo/cli/yandex-token.mjs url
```

Команда напечатает ссылку. Откройте её **в том браузере, где залогинен нужный
аккаунт**, нажмите «Разрешить» — Яндекс покажет 7-значный код.

Код живёт **10 минут**, поэтому сразу:

```bash
node seo/cli/yandex-token.mjs exchange 1234567
```

Токен запишется в `seo/.env` сам: копировать длинные строки руками не нужно,
и токен не придётся показывать в переписке.

### 1.5. Проверьте

```bash
node seo/cli/yandex-token.mjs check
```

Должны увидеть счётчик Метрики и `user_id` Вебмастера.

### 1.6. Срок жизни и продление

Токен действует около полугода. Продление идёт без вашего участия:

```bash
node seo/cli/yandex-token.mjs refresh
```

Эту команду можно поставить в расписание раз в месяц — с большим запасом.

**Что убивает токен мгновенно:** смена пароля Яндекс-аккаунта, включение или
выключение двухфакторной аутентификации, восстановление доступа, кнопка «Выйти
везде». Отзываются все токены аккаунта сразу и восстановлению не подлежат —
придётся пройти 1.4–1.5 заново. Если инструменты разом потеряли Яндекс,
первый вопрос — про пароль.

### 1.7. Какие API при этом открываются

| API | Что берём | Чем |
|---|---|---|
| `api-metrika.yandex.net/stat/v1/data` | визиты, источники, страницы входа, достижения целей | `metrika.mjs` |
| `api-metrika.yandex.net/management/v1` | создание целей, воронки, настроек счётчика | `goals.mjs` |
| `api-metrika.yandex.net/management/v1/.../offline_conversions/upload` | досылка оплат с сервера | `metrika_service.py` |
| `api.webmaster.yandex.net/v4` | запросы, показы, позиции, индексация, переобход | `webmaster.mjs` |

## 2. Google Search Console

Здесь другой механизм: не токен, а **сервисный аккаунт** — отдельная
«машинная учётка» с собственной почтой. Её ключ не протухает никогда, и
переподтверждать согласие в браузере не нужно.

Обычный OAuth здесь заметно хуже: пока приложение не прошло проверку Google,
доступ слетает раз в неделю — для автономной работы не годится.

**Карта не нужна.** Search Console API бесплатный и работает без биллинга.
Баннер «активировать пробный период» можно закрыть.

**Возможная помеха:** Google Cloud Console из России может не открываться —
понадобится VPN. Зайти туда нужно ровно один раз на 15 минут; дальше запросы
идут напрямую к API и работают штатно.

### 2.1. Создайте проект

<https://console.cloud.google.com/projectcreate> — название, например,
`seo-tools`. Организацию и расположение оставьте как есть. Убедитесь, что
вверху в переключателе выбран именно созданный проект.

### 2.2. Включите API

<https://console.cloud.google.com/apis/library/searchconsole.googleapis.com>
→ **Включить**. Кнопка сменилась на «Управление» — готово.

### 2.3. Создайте сервисный аккаунт

<https://console.cloud.google.com/iam-admin/serviceaccounts>

1. **+ Создать сервисный аккаунт**, название — например `seo-agent`.
2. Под полем появится **почта** вида
   `seo-agent@<проект>-123456.iam.gserviceaccount.com` — **скопируйте её**,
   она понадобится в 2.5.
3. **Создать и продолжить**.
4. Шаг «Предоставьте доступ к проекту» — **ничего не выбирайте**, роли здесь
   не нужны. **Продолжить** → **Готово**.

### 2.4. Скачайте ключ

Аккаунт → вкладка **«Ключи»** → **Добавить ключ** → **Создать новый ключ** →
тип **JSON** → **Создать**. Файл переложите в проект:

```
seo/keys/google-service-account.json
```

Папка `seo/keys/` закрыта в `.gitignore`. Переменную в `.env` заводить не
нужно — файл найдётся по этому пути сам. Общий вариант на все проекты:
`~/.seo-tools/google-service-account.json`.

**Файл скачивается один раз.** Потеряли — только создавать новый ключ.
Не пересылайте его в мессенджерах.

### 2.5. Главное: дайте аккаунту доступ в кабинет

Включить API недостаточно. Права на данные сайта выдаются отдельно, **внутри
самой Search Console**. Это тот шаг, который пропускают чаще всего, и потом не
понимают, почему список сайтов приходит пустым.

<https://search.google.com/search-console/users>

1. Выберите вверху свой ресурс.
2. **Добавить пользователя**.
3. Вставьте почту сервисного аккаунта целиком, вместе с хвостом
   `@...iam.gserviceaccount.com`.
4. Разрешение — **«Владелец»** (если недоступно — «Полный»).
   **«Ограниченный» не подойдёт**: с ним не работает отправка карты сайта,
   а проверка URL урезана.
5. **Добавить**.

Никаких файлов на сайт для этого класть не нужно. Если ресурсов два (домен и
префикс URL) — доступ выдаётся **каждому отдельно**, он не наследуется.

### 2.6. Проверьте

```bash
node seo/cli/gsc.mjs sites
```

403 сразу после добавления — подождите 5 минут, права расходятся не мгновенно.

## 3. PageSpeed Insights

Ключ для измерения скорости. Тот же ключ работает и для данных о реальных
посетителях Chrome (Chrome UX Report).

Без ключа API **физически не работает**: общая анонимная квота Google
исчерпана, приходит отказ «превышена квота». Документация Google до сих пор
пишет, что «работает и без ключа» — это устарело.

1. Включите два API в том же проекте Cloud:
   `pagespeedonline.googleapis.com` и `chromeuxreport.googleapis.com`.
2. <https://console.cloud.google.com/apis/credentials> →
   **+ Создать учётные данные** → **Ключ API**.
3. Ключ (начинается на `AIza`) впишите в `seo/.env`:

```
GOOGLE_API_KEY=AIza…
```

4. **Ограничения ключа — самое частое место, где всё ломается.** Если
   оставить «Не ограничивать ключ» — работает сразу. Если ограничивать, то в
   блоке «Ограничения API» отметить **оба** API из пункта 1: забыть один — и
   запрос вернёт 403 «Requests to this API … are blocked». Это не про права и
   не про сервисный аккаунт, а именно про список разрешённых ключу API.
   Ограничения по IP и referrer **не ставьте**: ключ дёргается из скрипта.

Проверка: `node seo/cli/psi.mjs`

## 4. IndexNow

Мгновенное уведомление Яндекса и Bing о том, что страница изменилась. Google
в этом протоколе не участвует — для него остаётся Search Console.

Регистрации нет вообще: ключ придумывается сам и кладётся файлом на сайт.

1. Придумайте ключ — 32 шестнадцатеричных символа:

```bash
node -e "console.log(require('node:crypto').randomBytes(16).toString('hex'))"
```

2. Впишите его в `seo/project.json` (`indexnowKey`) и положите в корень сайта
   файл `<ключ>.txt`, содержащий этот же ключ. После выкладки он должен
   открываться по адресу `https://<ваш-домен>/<ключ>.txt` и отдавать 200.
3. **Файл удалять нельзя никогда** — на нём держится подтверждение прав.
   Добавьте его проверку в смоук-тест после деплоя.

Дальше после каждой правки сайта:

```bash
node seo/cli/indexnow.mjs changed
```

Команда сравнивает собранный сайт с прошлым разом и отправляет **только
изменившиеся** страницы. Так и просит Яндекс: массовая переотправка одного и
того же ничего не ускоряет и выглядит как спам.

Ключ IndexNow не секрет: он и так открыто лежит на сайте.

## 5. Bing Webmaster Tools — необязательно

Ради двух вещей, которых больше нигде бесплатно нет: проверка частотности
любой фразы и подбор связанных запросов (то, за что обычно платят в Ahrefs
и Semrush).

Оговорка: данные из индекса Bing, а его доля в России — единицы процентов.
Цифры занижены в разы. Годится как компас («какая формулировка спрашивается
чаще»), а не как измеритель спроса.

1. <https://www.bing.com/webmasters/> → Sign in.
2. Добавьте сайт кнопкой **«Import your sites from Google Search Console»** —
   права подтянутся автоматически.
3. **Settings** → **API Access** → **API Key** → **Generate API Key**.
4. `BING_API_KEY=…` в `seo/.env`.

Проверка: `node seo/cli/bing.mjs sites`

## 6. Яндекс.Директ — только при платной рекламе

Если контекстной рекламы нет — **пропустите**. Вход стоит неделю ожидания, а
без открученного бюджета данных почти не будет.

Что важно понимать заранее: **частотности запросов (Вордстат) через API
Директа получить нельзя** — в пятой версии нет ни одного метода, который
возвращает число показов. Всё, что обещает бесплатную выгрузку частотности, —
это либо парсеры (нарушают правила Яндекса), либо платный Wordstat API в
Yandex Cloud. Спрос в этой связке измеряется Вебмастером: по своим показам.

Что доступ всё-таки даёт: проверку до 10 000 фраз разом (ищут такое вообще
или нет, без цифр) и реальные запросы людей, видевших ваши объявления —
лучший источник живых формулировок для заголовков.

Порядок:

1. **Заведите ОТДЕЛЬНОЕ приложение** с единственным правом `direct:api`.
   **Не дописывайте `direct:api` в приложение из раздела 1**: изменение прав
   отзывает все ранее выданные им токены — мгновенно потеряете и Метрику,
   и Вебмастер.
2. Создайте в Директе хотя бы одну кампанию (можно черновиком). Без неё
   раздел настроек API недоступен.
3. Подайте заявку на доступ, выбрав ClientID второго приложения, и опишите
   подробно, зачем он нужен. Рассмотрение до 7 дней; отклоняют чаще всего за
   расплывчатое описание.
4. После одобрения: `YANDEX_DIRECT_TOKEN=…`

## 7. Токен для сервера: офлайн-конверсии

Серверной части (досылка оплат в Метрику) нужен **свой** OAuth-токен в
переменной окружения `METRIKA_OAUTH_TOKEN`.

**Почему отдельный, а не тот же.** Токен из раздела 1 продлевается командой
`refresh`, и после продления прежнее значение перестаёт работать. Если сервер
держит его копию в своём `.env`, однажды он молча перестанет досылать оплаты,
и заметить это будет нечем, кроме строки в логе.

Как получить:

1. Зайдите на <https://oauth.yandex.ru> под аккаунтом, которому принадлежит
   счётчик.
2. Создайте приложение: платформа **Веб-сервисы**, Redirect URI —
   `https://oauth.yandex.ru/verification_code`.
3. Права: **Яндекс.Метрика** — «Получение статистики, чтение параметров своих
   и доверенных счётчиков» **и** «Управление своими счётчиками».
4. Получите токен по ссылке
   `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ID приложения>`.
5. Положите в серверный `.env` рядом с остальными секретами проекта:

```
METRIKA_OAUTH_TOKEN=<токен>
```

Пока токен не задан, всё остальное работает штатно — просто оплаты не
досылаются, а в логах будет строка «офлайн-конверсии выключены».

**Грабля деплоя:** если бэкенд живёт в Docker, обычный `restart` **не
перечитывает `.env`**. Нужно пересоздать контейнеры
(`up -d --force-recreate <сервисы>`), иначе переменная не появится,
а выглядеть это будет как «токен прописали, а не работает».

## 8. Переменные окружения: сводная таблица

| Переменная | Что это | Где взять | Обязательна |
|---|---|---|---|
| `YANDEX_CLIENT_ID` | ID приложения Яндекса | раздел 1.2 | да |
| `YANDEX_CLIENT_SECRET` | секрет приложения | раздел 1.2 | да |
| `YANDEX_OAUTH_TOKEN` | токен Метрики + Вебмастера | 1.4, **пишется сам** | да |
| `YANDEX_OAUTH_REFRESH` | для продления токена | 1.4, пишется сам | да |
| `YANDEX_OAUTH_EXPIRES` | когда истекает | 1.4, пишется сам | — |
| *файл* `seo/keys/google-service-account.json` | ключ сервисного аккаунта | 2.4 | для Google |
| `GOOGLE_SERVICE_ACCOUNT_KEY` | путь к ключу, если он в другом месте | 2.4 | нет |
| `GOOGLE_API_KEY` | ключ PageSpeed + Chrome UX | 3 | для скорости |
| `BING_API_KEY` | ключ Bing Webmaster | 5 | нет |
| `YANDEX_DIRECT_TOKEN` | токен Директа (ОТДЕЛЬНОЕ приложение) | 6 | нет |
| `METRIKA_OAUTH_TOKEN` | токен сервера для офлайн-конверсий | 7 | для оплат |

Не секретные настройки проекта (домен, номер счётчика, ресурс в Search
Console, `host_id` Вебмастера, ключ IndexNow) живут **не** в `.env`, а в
`seo/project.json` — он коммитится, потому что описывает проект, а не доступы.

### Где физически лежат ключи

```
~/.seo-tools/.env                          общий файл на все проекты одного владельца
~/.seo-tools/google-service-account.json   общий ключ Google
<проект>/seo/.env                          то, что у проекта своё (сильнее общего)
<проект>/seo/keys/                         локальный ключ Google
```

Токен Яндекса и ключ Google выданы **аккаунту, а не сайту**: один токен видит
все счётчики Метрики и все сайты в Вебмастере. Держать их копии в каждом
проекте — значит при продлении вспоминать, где ещё лежит копия, и однажды
забыть. Переменные окружения сильнее обоих файлов — можно подменить значение
на один запуск:

```bash
YANDEX_OAUTH_TOKEN=... node seo/cli/webmaster.mjs queries
```

### Безопасность

* Права на файлы с секретами — `600`. Инструмент выставляет их сам, когда
  пишет токен, но скопированный из примера файл получает `644`, то есть
  читается любым пользователем машины. Проверьте: `chmod 600 seo/.env`.
* `.env`, `keys/`, `data/` закрыты в `.gitignore` (файл лежит в `seo/`).
* Если ключ попал не туда — **отзывайте, не раздумывая**. Перевыпуск занимает
  минуты, разбор последствий утечки — недели.

### Как отозвать доступ

| Сервис | Где |
|---|---|
| Яндекс | <https://id.yandex.ru/personal/data-access> или `node seo/cli/yandex-token.mjs revoke --force` |
| Google | Cloud Console → сервисный аккаунт → «Ключи» → удалить (отвалится мгновенно) |
| Google API-ключ | Cloud Console → Credentials → удалить ключ |
| Bing | Settings → API Access → Delete → Generate |

## 9. Если что-то не работает

Начните всегда с `node seo/cli/doctor.mjs`.

| Симптом | Что это почти всегда |
|---|---|
| Яндекс перестал отвечать целиком | сменили пароль, включили/выключили 2FA или нажали «Выйти везде» — токен получить заново |
| Токен получен, но доступа нет | получали токен под другим аккаунтом Яндекса (п. 1.1) |
| Вебмастер отвечает, но данных нет | не отмечено право `webmaster:hostinfo` |
| Search Console: ключ рабочий, сайтов ноль | не выполнен шаг 2.5 — аккаунт не добавлен в кабинет |
| Search Console: 403 сразу после настройки | права расходятся 2–5 минут, подождите |
| PageSpeed: превышена квота | не задан `GOOGLE_API_KEY` |
| PageSpeed: «Requests to this API are blocked» | в ограничениях ключа отмечен не весь список API |
| IndexNow: 403 на все отправки | файл ключа не отдаёт 200 — сайт не выложен |
| Директ отвечает, но всё пусто | заявка не одобрена либо реклама не крутилась |
| Оплаты не появляются в Метрике | нет `METRIKA_OAUTH_TOKEN`, либо контейнеры не пересозданы, либо визит старше 21 дня |
