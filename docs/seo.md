# SEO дом-щенков.рф

Боевой адрес: `https://дом-щенков.рф` (в punycode `https://xn----dtbefzjjef0i.xn--p1ai`, так он записан в canonical,
sitemap и разметке). Превью на GitHub Pages закрыто от индексации, канонический адрес у всех страниц — боевой.

## Что делает сборка (`tools/build.py` → `tools/seo.py`)

На каждой странице (вместо `<!--seo-->` в `base.html.j2`):

| Что | Откуда |
|---|---|
| `<title>`, `meta description`, один `<h1>` | контекст маршрута; сборка предупреждает: title > 60 знаков без бренда в конце, description > 160 или < 70 знаков, H1 ≠ 1 |
| `link rel=canonical` | `site.seo.base_url` + адрес страницы |
| `meta robots` | `index, follow, max-image-preview:large`; `noindex, follow` — страницы из `site.seo.noindex` (политика конфиденциальности) и 404 |
| Open Graph + `twitter:card` | title без « \| дом-щенков.рф», description, адрес, первое фото страницы (или `og_image` в контексте, иначе `assets/img/og/og-default.jpg`) |
| Иконки | `favicon.ico` (16/32/48), `assets/icons/favicon.svg`, `apple-touch-icon.png` (180), `icon-192/512`, maskable 512, `site.webmanifest` |
| Коды подтверждения | `site.seo.yandex_verification`, `site.seo.google_verification` — пустые не выводятся |
| Яндекс Метрика | `site.seo.yandex_metrika` — номер счётчика; пустой — счётчика нет |
| JSON-LD | `BreadcrumbList` на всех внутренних страницах; `WebSite` + `PetStore` (организация) на главной и в контактах; страницы сами добавляют `FAQPage` (блок вопросов) и `BlogPosting` (статьи) |
| Защита превью | на `*.github.io` скрипт дописывает `noindex, nofollow` |

Файлы в корне:

- `sitemap.xml` — индексируемые **выложенные** страницы (`src/data/publish.json`, см. «Выпуск по этапам» в brief);
  ссылки на ещё не выложенные страницы получают `rel="nofollow"` и не ведут роботов в 404; `lastmod` — день, когда страница последний раз изменилась
  (хеш хранится в `.build-manifest.json → lastmod`; смена только версии CSS/JS дату не двигает);
  `priority`/`changefreq` по типу страницы (главная 1.0, каталог и породы 0.9, окрасы и цены 0.8, щенки 0.7…).
- `robots.txt` — всё открыто, кроме `/_kit/`; для Яндекса `Clean-param` для фильтров каталога
  (`breed`, `sex`, `status`), тем блога (`tema`) и рекламных меток; ссылка на sitemap.
- `404.html` — своя страница «Страница не найдена» (noindex): ссылки на каталог, главную и четыре породы.
  Работает на любой глубине адреса и на превью (сама ставит `<base>`).
- `site.webmanifest` — название, цвета и иконки.

## Правила для страниц

- Один H1 с главным запросом страницы, до двух строк. Title — запрос + «в Москве», где уместно.
  Длина: ≤ 60 знаков до « | дом-щенков.рф». Бренд в конце поисковик может обрезать (его и так видно в сниппете),
  запрос — нет.
- H1 называет щенка или породу, title — это фраза, которую ищут, и начинается с «Купить» (как у магазинов: H1
  «Наушники Apple AirPods Pro 3», title «Купить наушники…»; владелец 22.10). Так на продающих страницах:
  главная и каталог — «Купить щенка в Москве — …», порода — «Купить щенка мальтипу в Москве — питомник дом-щенков.рф»,
  окрас — «Купить абрикосового той-пуделя в Москве», щенок — «Купить абрикосового щенка той-пуделя в Москве»
  (с поколением мальтипу: «… мальтипу F1b мини …»), города — «Купить щенка в Казани от заводчика».
  Кличку щенка в title не пишем никогда: её не ищут. У щенков одного окраса title поэтому совпадает, различает их
  description (кличка, пол, возраст). Окрас склоняет `_lib.adj_gen` («рыжий» → «рыжего», «пегий» → «пегого»).
  Цены — «Сколько стоит щенок … — цены в Москве»; виды и окрасы, сравнения, блог, вопросы, документы, отзывы,
  контакты, правовые — без «купить»: там другой запрос, «купить» спорил бы с продающими страницами.
  Description — 110–160 знаков, со смыслом и призывом.
- Микроразметка — только того, что есть на странице. `Product`/`Offer` не ставим, пока на сайте нет цен
  (без цены Google и Яндекс считают разметку товара ошибочной). Рейтинг организации — только с настоящими отзывами.
- Картинкам с содержанием — осмысленный `alt`; декоративным (кружки-лица, миниатюры галереи) — `alt=""`.

## Запуск сайта — по шагам

1. Домен `дом-щенков.рф` → A-запись на IP сервера (и `www` тоже).
2. Сервер: по шагам в [`DEPLOY.md`](../DEPLOY.md) (`server-setup.sh`, затем `deploy.sh`). nginx ставится из
   `backend/deploy/nginx.conf`: правила отсюда (один адрес, 404, кэш, gzip) + API форм и админ-панель.
   `deploy.sh` сам проверяет: `/maltipu/index.html` → `/maltipu/`, несуществующий адрес — код 404 и наша страница.
   Вручную: `http://` и `www` ведут на `https://дом-щенков.рф/` одним 301; `/maltipu` → `/maltipu/`.
3. Заменить заглушки в `src/data/site.json`: телефон, почта, адрес, ссылки мессенджеров, рейтинги — они уходят
   в разметку организации. Пересобрать.
4. **Яндекс Вебмастер**: добавить `https://дом-щенков.рф`, подтвердить мета-тегом (код → `site.seo.yandex_verification`),
   отправить `sitemap.xml`, указать регион «Москва», связать с карточкой в Яндекс Бизнесе.
5. **Яндекс Бизнес**: карточка питомника (адрес, телефон, часы, фото, сайт) — для Карт и локальной выдачи.
6. **Google Search Console**: подтвердить (код → `site.seo.google_verification`), отправить sitemap.
7. **Яндекс Метрика**: создать счётчик, номер → `site.seo.yandex_metrika`, настроить цели на отправку заявок.
8. Через 1–2 недели: в Вебмастере — ошибки индексации и разметки, в Метрике — первые визиты.

## Переезд на дом-щенков.рф (02.11.2026)

Первый адрес домщенков.рф (без дефиса) работал с 19.10 по 31.10, затем у Beget отказал DNS. Новый адрес —
дом-щенков.рф; www, dom-shchenkov.ru и старый домщенков.рф отвечают одним 301 на ту же страницу нового адреса
(nginx, `backend/deploy/domain.sh`). canonical, `sitemap.xml`, `robots.txt`, Open Graph и разметка — на новом адресе.

**Не закрывать старый домен от индексации** (robots.txt `Disallow`, noindex, «Удаление» в Search Console): робот
тогда не увидит 301, и накопленное старым адресом (позиции, ссылки) не перейдёт на новый. 301 сам убирает старые
адреса из выдачи и ставит вместо них новые. Старый домен продлевать не меньше года; его A-записи — на сервер.

**Яндекс Вебмастер**
1. Добавить сайт `https://дом-щенков.рф`, подтвердить: мета-тег (код → `site.seo.yandex_verification`, пересобрать) или
   DNS-запись TXT в Timeweb.
2. Отправить `https://дом-щенков.рф/sitemap.xml`, регион — Москва.
3. Когда старый адрес снова открывается и отвечает 301: в карточке старого сайта «Индексирование → Переезд сайта»
   на дом-щенков.рф (склейка зеркал, обычно 2–4 недели).
4. Метрика: тот же счётчик. «Настройка → Адрес сайта» → дом-щенков.рф, старый — дополнительным адресом; если включено
   «Принимать данные только с указанных адресов» — добавить новый. Привязать счётчик к новому сайту в Вебмастере.

**Google Search Console**
1. Новый ресурс: «Доменный ресурс» `дом-щенков.рф` (подтверждение TXT-записью в DNS Timeweb — сразу на все поддомены,
   http и https) или «Ресурс с префиксом URL» `https://дом-щенков.рф/` (мета-тег → `site.seo.google_verification`).
2. Отправить sitemap.
3. Когда старый адрес отвечает 301: в ресурсе старого домена «Настройки → Смена адреса» → новый ресурс. Оба ресурса
   должны быть подтверждены одним аккаунтом. Старый ресурс не удалять.

**Ссылки на сайт снаружи** (карточки Яндекс Карт и 2ГИС, Авито, соцсети, реклама Директа) — поменять на
дом-щенков.рф: 301 их довезёт, но прямая ссылка надёжнее.
