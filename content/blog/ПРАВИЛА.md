# Правила статьи блога домщенков.рф

Короткий контракт для писателя и редактора. Всё, что проверяется скриптом, проверяет скрипт:
`python3 tools/blog/factory.py lint <slug>`. Модели остаётся смысл: польза, точность, тон.

## Для кого и зачем

Читатель — будущий или новый хозяин щенка. Он пришёл из поиска со своим вопросом. Статья:
1. отвечает на этот вопрос в первых двух абзацах;
2. даёт план действий — по шагам, таблицей, списком;
3. в конце мягко ведёт к щенкам питомника (cta), без давления.

## Тон

- Короткие предложения. Тепло и конкретно. На «вы».
- Без воды и вступлений «в наше время». Без «лучший», «№1», без цен щенков.
- Факты о питомнике — только из `content/blog/факты.md`. Цифры о породах — оттуда же.
- Тема о здоровье (`check` в карточке): только общепринятое, без доз, лекарств и диагнозов.
  Где цена ошибки высока — «покажите ветеринару». Спорное называем спорным.
- Не придумывать отзывы, истории «наших выпускников», имена хозяев, статистику.

## Объём и структура

- 700–1100 слов текста (скрипт: ошибка меньше 600, замечание больше 1400). Это 5–8 минут чтения.
- 4–7 разделов (`sections`), у каждого `id` латиницей, `toc` до 28 знаков, `h2` с ключом раздела.
- Минимум одна таблица, один список, одна врезка (`callout`). FAQ — 3–5 вопросов, ответы 1–3 предложения.
- `title` ≤ 60 знаков и заканчивается на « | домщенков.рф»; `description` 110–160 знаков;
  `card_line` ≤ 60; `h1` ≤ 60.
- Главный запрос карточки (`pk`) — в title, h1 или lead, и во вступлении (`intro`). Дополнительные — по одному
  в разделы, естественно. Без переспама.

## Фото — минимум 3 в тексте

- `figure` — одно горизонтальное фото (1 шт.), `photos` — две вертикальные рядом (2 шт.).
  Минимум 3 фото в теле статьи, плюс `cover` (карточка в списке) и `hero` (шапка; для статьи о породе можно `null` —
  возьмётся студийное фото породы).
- Фото берём из подсказки `factory.py brief <slug>`: это реальные фото щенков питомника с подписями.
  Одно фото — один раз в статье. Реже используем фото, которые уже стоят в других статьях.
- `alt` описывает, что на фото. Не выдумывать (породу, окрас, действие), чего не видно.
- Иллюстрация Figma (`/assets/img/blog/<slug>-N.jpg`) — только сцена без претензии на «наш щенок»:
  предметы, руки, процесс. Подпись нейтральная: «Пример набора для щенка», а не «Наш выпускник».

## Ссылки

- **Месяц 1 плана — ни одной ссылки в тексте.**
- С месяца 2 — до 3 ссылок: `[текст](/blog/slug/)` или страница сайта (`/maltipu/`, `/shchenki/`, `/dostavka/`…).
  Только на то, что уже вышло; список разрешённых — в брифе. Ссылка — внутри абзаца, где читателю нужен
  материал, не списком в конце.
- Кнопки внизу (cta), «Читайте также» и форма — это шаблон страницы, их не пишем.

## Формат файла `content/blog/posts/<slug>.json`

```json
{
  "slug": "chto-kupit-shchenku",
  "breed": null,
  "keywords": ["что нужно купить для щенка", "список вещей для щенка"],
  "status": "draft",
  "sources": [],
  "post": {
    "title": "Что купить щенку: список до переезда | домщенков.рф",
    "description": "110–160 знаков: о чём статья и какая польза.",
    "h1": "Что купить щенку до переезда",
    "crumb": "Что купить щенку",
    "eyebrow": "Выбор щенка · подготовка",
    "lead": "Одна строка под H1, до 90 знаков",
    "topic": "Выбор щенка",
    "card_line": "Строка карточки в списке, до 60 знаков",
    "cover": {"src": "/assets/img/….jpg", "alt": "…"},
    "hero": {"src": "/assets/img/….jpg", "alt": "…"},
    "intro": "Вступление 2–4 предложения: прямой ответ на вопрос.",
    "sections": [
      {"id": "son", "toc": "Место для сна", "h2": "Где будет спать щенок", "blocks": [
        {"p": "Абзац. **Жирный** — редко."},
        {"ul": ["Пункт", "Пункт"]},
        {"figure": {"src": "/assets/img/….jpg", "alt": "…"}},
        {"table": {"caption": "Подпись таблицы", "head": ["Вещь", "Зачем", "Когда"], "rows": [["…", "…", "…"]]}},
        {"callout": {"kind": "love", "title": "Совет питомника", "text": "…"}},
        {"photos": [{"src": "/assets/img/….jpg", "alt": "…"}, {"src": "/assets/img/….jpg", "alt": "…"}]}
      ]}
    ],
    "faq_title": "Вопросы о …",
    "faq": [{"q": "Вопрос?", "a": "Ответ."}],
    "cta": {"title": "Призыв по смыслу темы", "line": "Одна строка пользы"}
  }
}
```

- Типы блоков: `p`, `h3`, `ul`, `ol`, `table`, `callout` (`kind`: `love` — совет питомника, `warn` — риск,
  `info` — справка, `ok` — хорошо/можно), `proscons` (`{"pros": […], "cons": […]}`), `figure`, `photos`.
- Разметка в тексте: `**жирный**`, `[ссылка](/url/)`. HTML не писать.
- `topic` — одна из рубрик: Выбор щенка, Характер, Уход, Кормление, Воспитание, Здоровье.
- `breed` — `maltipu`, `francuzskij-buldog`, `toj-pudel`, `border-kolli` или `null` (общая статья).
- `cta.button` и `cta.second` не нужны: шаблон подставит «Всё о породе» / «Смотреть щенков».
- `sources` — для тем о здоровье: `[{"title": "…", "url": "…"}]`, только то, что реально проверено.

## Редактор: блокеры и пожелания

**Блокер** (статья не выходит): неверный или выдуманный факт; факт о питомнике не из `факты.md`; опасный
совет о здоровье (доза, «не идите к врачу»); противоречие цифрам уже вышедших статей; текст не отвечает на
главный запрос; фото не совпадает с подписью или темой; ошибка проверки скрипта.

**Пожелание** (статья выходит): стиль, порядок абзацев, объём чуть за границей, формулировку можно точнее.

Редактор не переписывает текст. Возвращает блокеры адресно: раздел, что не так, как исправить.
Один круг правок. Не исправлено со второго раза — статья остаётся черновиком и ждёт человека.
