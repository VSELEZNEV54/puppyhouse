# Контент-завод блога дом-щенков.рф

Статьи пишутся, проверяются, иллюстрируются и выходят на сайт сами. Человек может читать готовое и
откладывать лишнее, но не обязан. Основа — методология редакции seo-news (пять агентов, критик, автопубликация),
упрощённая под блог питомника: меньше вызовов модели, больше работы делает скрипт.

## Как это работает

```
content/blog/plan.json — база всех тем: 6 месяцев, 188 карточек (13 «Полезных материалов» + 175 статей)
        │
        ▼  /статьи  (Claude Code: вручную или по расписанию, 8 статей в неделю)
   factory.py next      → какие темы писать (0 токенов)
   Figma generate_image → 1 иллюстрация, если в карточке есть сцена (кредиты Figma, не токены)
   blog-writer ×3       → статьи параллельно; factory.py lint до чистоты (0 токенов на проверку)
   blog-editor          → смысл, факты, безопасность → approve или блокеры (1 круг правок)
   git push             → content/blog/posts/*.json + assets/img/blog/*
        │
        ▼  GitHub Action «Блог — публикация», каждый день ~09:20 МСК
   factory.py publish   → запуск материалов / одна статья в день публикации → published.json
   build.py (+ --full)  → страница, список /blog/, sitemap, JSON-LD с датой
   commit «Автопубликация …»
        │
        ▼  сервер, dsh autoupdate (раз в 5 минут): новый коммит → сайт
```

## Что упрощено по сравнению с seo-news

| Было (seo-news) | Стало | Зачем |
|---|---|---|
| Планировщик на каждую статью | План на 6 месяцев готов заранее, карточка = бриф | −1 вызов модели на статью |
| Ресёрчер с досье из первоисточников | Справка `факты.md` + до 3 поисков только для тем о здоровье (⚕) | Блог о щенках, не о законах: факты питомника стабильны |
| Структуратор со SEO-скелетом | Угол и ключи — в карточке, структура — в ПРАВИЛАХ | −1 вызов |
| Критик до 3 кругов | Скрипт `lint` (формат, SEO, фото, ссылки, запреты) + редактор, 1 круг | Формальное проверяет код бесплатно |
| Статья 900–1800 слов | 700–1100 слов, как уже вышедшие статьи сайта | Меньше токенов, легче читать с телефона |
| Telegram-версия | Нет (можно добавить позже) | Не просили |
| 7 вызовов, 200–800 тыс. токенов и 15–25 минут на статью | 2 вызова; пилот 11.11.2026: писатель ~80 тыс. токенов и 40 с, редактор ~85 тыс. и 20 с | Дешевле в 1,5–5 раз, быстрее в 10+ раз |

Токены пилота — с учётом служебного контекста агента общего типа (большой набор инструментов, в основном из кэша). У `blog-writer` и `blog-editor` инструментов меньше — ожидаю ниже, это прогноз, замерить на первом плановом запуске.

Что сохранено: файлы на диске — истина (готовое не переписывается); блокеры отдельно от пожеланий;
публикуется только одобренное; ссылки только на вышедшее; расписание задаёт крон, а не даты в плане.

## Роли

| Кто | Что делает | Где |
|---|---|---|
| Контент-план | 188 карточек: тема, главный и дополнительные запросы, угол, призыв, фото, сцена иллюстрации, ссылки | `plan.json`, читаемо — `план.md` |
| Писатель (`blog-writer`, Sonnet) | Пишет статью по брифу в JSON, гоняет `lint` до чистоты | `.claude/agents/blog-writer.md` |
| Редактор (`blog-editor`, Sonnet) | Польза, факты из `факты.md`, здоровье, фото → `approve` или блокеры | `.claude/agents/blog-editor.md` |
| Выпускающий (`/статьи`) | Берёт темы, делает иллюстрации, запускает писателей и редактора, коммитит | `.claude/commands/статьи.md` |
| Скрипт завода | План с датами, бриф, подбор фото, проверка, публикация, снятие | `tools/blog/factory.py` |
| Публикатор | Запуск материалов, затем статья в день публикации; сборка, коммит | `.github/workflows/blog-publish.yml` |
| Сервер | Забирает коммит и выкладывает | `dsh autoupdate` (DEPLOY.md) |

## Файлы

```
content/blog/plan.json          контент-план (порядок = порядок выхода)
content/blog/план.md            он же таблицей со статусами (генерирует factory.py plan)
content/blog/ПРАВИЛА.md         контракт статьи: тон, объём, фото, ссылки, формат JSON, блокеры
content/blog/факты.md           что можно говорить о питомнике и породах
content/blog/posts/<slug>.json  статьи завода (status: draft → approved; hold — не выпускать)
content/blog/published.json     что вышло и когда (пишет только publish)
content/blog/photos.json        каталог фото сайта с подписями (factory.py photos --rebuild)
content/blog/figma.json         стиль иллюстраций (эталон, шаблон запроса), файл Figma и модель
content/blog/illustrations.json откуда каждая иллюстрация: запрос, модель, версия стиля (пишет factory.py img)
assets/img/blog/<slug>-N.jpg    иллюстрации
src/data/blog-posts.json        первые 11 статей (написаны раньше, стоят в плане как ready; 10 из них — материалы)
```

## Контент-план на 6 месяцев

База всех тем — `plan.json` (читаемо — `план.md` с датами и статусами). Темы и ключи — из семантического ядра
(таблица «Анализ по СОБАЧКАМ»: листы «Семантика», «Контент», «Сезонность»), порядок — по сезонности спроса.

| Месяц | Даты | Тема месяца | Статей |
|---|---|---|---|
| — | 12.11.2026 | «Полезные материалы»: как выбрать щенка + характер, уход, кормление каждой из 4 пород | 13 |
| 1 | 23.11–22.12 | Разгон: первые недели со щенком, зима, Новый год | 24 |
| 2 | 23.12–22.01 | Январский пик покупок: выбор породы и щенка, первые месяцы | 31 |
| 3 | 23.01–22.02 | Воспитание, команды и здоровье щенка | 31 |
| 4 | 23.02–22.03 | Здоровье, груминг, документы и выставки | 28 |
| 5 | 23.03–22.04 | Весна: линька, клещи, прогулки и город | 31 |
| 6 | 23.04–22.05 | Май: клещи, дача, жара, подготовка к летнему пику | 30 |

«Полезные материалы» (`series: base`) — не статьи ленты, а справочник: на `/blog/` они стоят отдельным блоком
над списком статей и в список не попадают.

## Расписание

- **Запуск:** 12.11.2026 разом вышли 13 «Полезных материалов» (`schedule.launch`).
- **Статьи:** с 23.11.2026 по одной в день публикации, к 10:00 МСК (`schedule.start`). Разгон: неделя 1 —
  3 статьи (пн 23.11, ср 25.11, пт 27.11), неделя 2 — 5 (30.11–4.12, пн–пт), с 7.12 — каждый день.
  Отсчёт разгона — от первой вышедшей статьи. Даты в `план.md` ориентировочные: если статья не готова, выходит
  следующая готовая.
- **Генерация:** статья в день = 7 в неделю. Запуск `/статьи 8` раз в неделю (или запланированная задача Claude
  Code в облаке с тем же текстом), чтобы в буфере было 7+ готовых. На 12.11.2026 написан весь месяц 1 (24 статьи):
  генерацию месяца 2 начать до 10.12.
- **Буфер пуст:** Action падает с кодом 3, GitHub присылает письмо. Сайт при этом не ломается.

## Ссылки

- «Полезные материалы» до 23.12.2026 и статьи месяца 1 — ни одной ссылки в тексте: ссылки показываются простым
  текстом (`published.json → links: 0`), сам текст не меняется. С 23.12 (`base_links_from`) ссылки в материалах
  включаются сами (`publish` ставит `links: 3`).
- С месяца 2 — до 3 ссылок, только на вышедшие статьи и страницы сайта. Список разрешённых — в брифе,
  проверка — `lint` и повторно `publish`.
- Блоки шаблона («Читайте также», кнопки, форма) — не ссылки в тексте, они есть на всех страницах.

## Фото и иллюстрации

- Минимум 3 фото в тексте статьи (`lint` не пропустит меньше), плюс обложка и шапка.
- Основа — реальные фото щенков питомника (≈300 в `assets/img`). `factory.py brief` подбирает кандидатов по
  породе и словам из карточки и понижает те, что уже стоят в других статьях. 0 токенов.
- Иллюстрации Figma — для сцен, которых нет на фото (набор вещей, руки стригут когти, лапы в тазике).
  Одна на статью и только при `illus_en` в карточке: 25 из 188 тем. Не прошла проверку стиля дважды —
  статья выходит с реальными фото. Генерация тратит
  AI-кредиты Figma команды «Moon дизайн-студия» (Pro, Full seat), а не токены Claude. В пределах месячной
  квоты кредитов — без доплат; сверх квоты Figma берёт деньги.
- Иллюстрация — не «наш щенок»: в подписи нет породы, «наш», «выпускник» (`lint` проверяет).

## Стиль иллюстраций: эталон

Эталон утвердил владелец 11.11.2026 — иллюстрация к статье «Что купить щенку до переезда»:
`/assets/img/blog/chto-kupit-shchenku-1.jpg`. Все следующие картинки — в том же стиле.

![Эталон стиля](../../assets/img/blog/chto-kupit-shchenku-1.jpg)

Стиль «Тёплый скандинавский дом» (версия 3):
- фотореализм, как тёплый кадр журнала о доме: спокойно и уютно, средняя экспозиция, не «светлая картинка»;
- мягкий рассеянный дневной свет из окна слева, тёплый сливочный, но не закатный и не оранжевый; тени
  настоящие, тёплые коричневые; самое светлое в кадре — предмет, края чуть темнее центра;
- палитра — крем, айвори, тёплый бежевый, песок, светлый медовый дуб; белое — айвори и крем; тепло даёт
  материал (дуб, джут, лён), а не цветной фильтр; акценты маленькие и приглушённые;
- дуб светлый, матовый, не тёмно-янтарный и не выбеленный; стены — кремовая штукатурка; окно — только уголок
  за прозрачной шторой; фон — размытая обжитая комната (диван, корзина с пледом, растение);
- камера на уровне колена, 35 мм, пол по диагонали, передний план пустой, вещи — одной группой;
- крупный план — 85 мм, только нужная деталь, руки — кисти и предплечья, без лиц и туловища;
- щенок — маленький, круглый, пушистый, кремовый или абрикосовый, занят своим делом, не позирует;
- без текста, логотипов, техники, тёмного металла, мутной воды; без улицы и снега — зима снимается дома.

Как это закреплено, чтобы не зависеть от памяти модели:
- один шаблон запроса на все картинки — `content/blog/figma.json → style` (общий стиль + интерьер + тип кадра
  `home`, `closeup`, `flatlay`, `car` + щенок + запреты); сцена — из карточки плана (`illus_en`);
- `factory.py illus <slug>` собирает запрос, руками его не пишут; модель и размер зафиксированы;
- проверка по цифрам — `factory.py look` (пороги в `figma.json → style.look`): светлота, глубина теней,
  пересвет, теплота и затемнение краёв относительно эталона. `factory.py img` не сохранит картинку, которая не
  прошла; одна перегенерация, потом статья обходится реальными фото;
- `content/blog/illustrations.json` хранит для каждой картинки точный запрос, модель, версию стиля и цифры.

Как подбирался шаблон (11.11.2026, три круга, проверка независимыми проверяющими против эталона):
- версия 1 — бледно, выбеленный пол, пересвеченные окна, голые стены: 4 кадра из 4 — «не та серия»;
- версия 2 — бледность ушла, но цвет перегрет в оранжевый: 5 кадров из 5 не приняты;
- версия 3 — тепло от материалов, светлый медовый дуб, окно уголком, пустой передний план. Пороги проверки по
  цифрам подобраны так, что все 9 забракованных кадров не проходят, а эталон и реальное фото питомника проходят.

Поменять стиль может только владелец: правка `style`, `version` +1, новый эталон.

## Команды

```bash
python3 tools/blog/factory.py status        # что вышло, что в буфере, на сколько хватит
python3 tools/blog/factory.py plan          # обновить план.md
python3 tools/blog/factory.py lint          # проверить все черновики
python3 tools/blog/factory.py hold <slug>   # не выпускать (и для статей, написанных раньше)
python3 tools/blog/factory.py approve <slug>
python3 tools/blog/factory.py unpublish <slug>   # снять с сайта, затем сборка и коммит
python3 tools/build.py --all                # весь сайт с черновиками в _all/ (локально, не коммитится)
```

Превью черновиков: после ближайшей автопубликации они есть в `full/blog/<slug>/` (GitHub Pages, закрыто от
индексации).

## Продление плана

За месяц до конца плана (в апреле 2027): «Добавь месяцы 7–8 в content/blog/plan.json по README и ПРАВИЛАМ:
по 30 тем, не повторять вышедшие, учесть сезонность и запросы из Яндекс Вебмастера». Это один вызов модели.
После правки — `factory.py plan` (он же проверит, что слаги не повторяются).

## Уроки seo-news, которые здесь учтены

1. Критик, который валит статью за стиль, не выпускает ничего → блокеры отдельно от пожеланий.
2. Ссылка на невышедшую статью — 404 → ссылки проверяются при записи и ещё раз в день публикации.
3. Готовое не переписывать → `next` отдаёт только темы без файла.
4. Публиковать только одобренное → `publish` берёт `approved`/`ready` и прогоняет `lint`.
5. Пустой буфер не должен быть тихим → падение Action и письмо.
6. Статьи-клоны с заменённым названием породы → в карточке каждой породной темы написано, чем она отличается.
7. Факт о питомнике, которого нет, хуже отсутствия факта → один файл фактов, редактор сверяет с ним.
